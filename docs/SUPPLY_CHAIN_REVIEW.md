# Post-launch supply-chain and permission review

Focused source/dependency review, not an independent audit or certification. The native dependency follow-up rebuilds the userspace library; independent rebuild and fresh-machine privileged acceptance remain unverified. The deterministic partial CycloneDX inventory is generated by `tools/generate_sbom.py`; it must not be presented as complete runtime or license coverage.

## Executed inventory and advisory checks

The [CycloneDX 1.6 JSON](ironclad-build-inventory.cdx.json) was generated twice offline with identical SHA-256 `46acac9493291136375b86eae90cd6ec607842e8adc9ea81504e8e675ca8ef5b` and validated against the official 1.6 JSON schemas with zero validation errors. It contains 173 components: 160 Cargo lock records (148 registry, 12 local/patched), bundled KRSI, optional Falco, nine external requirements, and two GUI-test-only dependencies. Python declares no third-party runtime dependencies. Registry hashes describe crate archives, not linked library bytes. Cargo resolution edges are not proof of target features or linked runtime membership.

Generator checks bind the shipped native library/archive, embedded Cargo.lock, both patches, source-input hashes and BPF digest to recorded provenance. KRSI's Cargo package identity `0.1.0` is distinct from candidate fork identity `0.2.0-ironclad.2`. Local patched components deliberately have no unmodified registry purl. Full Falco transitive inventory, installed system versions and complete license/linked-component review remain missing.

## Source review and controls

| Boundary | Existing control and reviewed source | Remaining limitation |
|---|---|---|
| CI/publication | `.github/workflows/*.yml`: immutable action SHAs, read-only repository permissions, checkout credentials not persisted; candidate upload only. `tools/verify_publication.py`: bounded nested-archive checks. | GitHub workflow success is not native live acceptance. Pattern scanning cannot detect every secret. Host runner preparation must stay disposable. |
| Native download | `sensor_package.py`: explicit authorization, HTTPS source pins, bounded download, redirect restrictions and archive/library verification. | Hashes establish expected bytes, not publisher signatures or independently reproduced builds. |
| Native build | `tools/build_krsi_component.py`: pinned source inputs, patches, lock and anonymized paths; embedded build-info records Rust 1.99.1. | Recipe now rejects a different Rust version and allowlists its build environment. Builds use isolated public caches and no network. No independent rebuild performed. |
| Install/remove | `packaging/manage.py`: allowlisted files, no-follow/exclusive creation, receipt validation, preserved changed/extra files; new diagnostic-unit refusal. | Real package/polkit/user-manager lifecycle and reboot require VM acceptance. Git-manager removal has its own lifecycle; follow documented pre-removal steps. |
| Privileged helper | `sensor.py`, `sensor_service.py`, `sensor_policy.py`: exact-plan binding, digest/owner/expiry checks, fixed operations, health verification and service restrictions. | Kernel capabilities remain powerful; same-user/root/kernel compromise excluded. `auth_admin_keep` may cache authorization. Static review does not prove kernel event coverage. |
| Network jobs | `protection_updates.py`, `scheduling.py`: opt-in unit creation, exact unit/ownership validation and bounded allowed operations; diagnostics offline. | Actual scheduling and failed activation rollback need separate-machine confirmation. |
| AI | `advisor.py`, `model.py`, `Workspace.qml`: bounded redacted context, known response IDs, untrusted plain-text answers, typed independently approved actions. Post-launch GUI fix requires explicit AI action. | Provider CLI restrictions are not OS isolation against a compromised client; client authentication/retention remains external. Unknown sensitive text may escape redaction. No remote/model content may inherit tool or approval authority. |
